# 阶段 3：从单层嘴部贴图到多层嘴部结构

## 为什么下一步做多层嘴部

当前 Demo 已经有多张嘴部 PNG 贴图，并且能根据音频特征或摄像头关键点切换嘴型。

继续优化单层贴图当然还能变好，但会很快遇到上限：

- 嘴巴张开时，上下唇、牙齿、口腔阴影无法独立运动。
- 大开口时，整张贴图缩放会显得像图片被拉伸，而不是嘴部结构在变化。
- 嘴角、唇缝、牙齿露出这些细节很难只靠一张图稳定表达。

所以更适合的下一步不是继续堆更多单层嘴型，而是学习：

```text
嘴部结构分层 -> 每层独立绘制 -> 用同一组驱动参数控制不同层
```

这一步仍然属于 2D 数字人学习，不需要马上引入 3D、Live2D 或实时流式架构。

## 学习目标

完成这一阶段后，应能解释：

1. 为什么嘴部要拆层，而不是只换整张嘴图。
2. 上唇、下唇、牙齿、口腔阴影分别应该怎么运动。
3. 同一个 `openness` 参数如何驱动不同图层产生不同幅度的变化。
4. 为什么分层后更容易做眨眼、呼吸、表情等角色表现。

## 建议拆成 4 个小任务

### 任务 1：冻结当前单层版本

目标：把 `single_layer_mouth_demo/` 当作基线版本保留下来。

建议：

- 不再在这个目录里继续大幅增加嘴型复杂度。
- 只修明显 bug 或补文档。
- 后续新实验另开目录，例如 `layered_mouth_demo/`。

完成标准：

- 当前 Demo 仍然可运行。
- README 能说明它的定位和运行方式。

### 任务 2：准备多层嘴部素材结构

目标：先建立素材组织方式，不急着做复杂动画。

建议目录：

```text
layered_mouth_demo/
└── static/
    └── mouth_layers/
        ├── mouth_shadow.png
        ├── teeth_upper.png
        ├── teeth_lower.png
        ├── lip_upper.png
        └── lip_lower.png
```

如果暂时没有精细素材，可以先用简单 PNG 占位。重点是理解“层”的概念，而不是一开始追求美术质量。

完成标准：

- Canvas 能按固定顺序绘制多个嘴部图层。
- 所有图层都能对齐到同一个嘴部 ROI。

### 任务 3：用开口参数驱动上下层

目标：让不同图层响应同一个开口参数，但运动方式不同。

建议规则：

```text
openness = 0 时：
  上唇、下唇靠近
  牙齿和口腔阴影基本不可见

openness 增大时：
  上唇略微上移
  下唇明显下移
  口腔阴影逐渐显示
  牙齿根据开口程度部分显示
```

完成标准：

- 嘴巴张开不再只是整张贴图变高。
- 能清楚看到“上唇、下唇、口腔内部”在分开运动。

### 任务 4：把现有驱动接到多层渲染器

目标：复用现在已有的音频特征和摄像头关键点逻辑，只替换绘制方式。

建议保留现有驱动输出：

```js
{
  shape,
  openness,
  roundness,
  widthness
}
```

然后新增一个多层渲染器：

```text
mouthDriver 负责判断状态
layeredMouthRenderer 负责分层绘制
```

完成标准：

- 音频模式仍然能驱动嘴部开合。
- 摄像头模式仍然能驱动嘴部开合。
- 代码里能看出“驱动”和“渲染”是分开的。

## 推荐实现顺序

先不要一次性复制整个当前目录再大改。建议先做一个更小的新实验：

```text
第 1 步：新建 layered_mouth_demo/
第 2 步：复制最小 FastAPI + Canvas 页面
第 3 步：只画头像和 5 个嘴部图层
第 4 步：用一个滑块手动控制 openness
第 5 步：确认分层运动自然后，再接回音频驱动
```

这样做的好处是学习重点清楚：

```text
先理解多层嘴部渲染，再理解多层嘴部驱动
```

## 暂时不建议做的事

当前阶段不建议马上做：

- LLM 对话大脑
- WebSocket 流式 TTS
- 3D 数字人
- Live2D / Unity / Unreal 集成
- 复杂音素级对齐

这些方向都值得学，但它们会把问题扩大到工程架构、实时通信、模型接入和资产管线。现在更应该先把 2D 嘴部表现的基本结构吃透。

## 这一阶段帮助理解什么

这一阶段的核心收获是：

```text
数字人的“像不像在说话”，不只取决于音频识别准不准，也取决于嘴部结构是否能被合理拆分和驱动。
```
