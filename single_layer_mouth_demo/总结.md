# 单层贴图嘴型方案总结

## 启动方式

uvicorn main:app --reload

## 当前方案定位

这个目录保存的是当前阶段的 `单层贴图 + 局部形变` 数字人嘴型实验版本。

它的目标不是做最终产品，而是验证下面这条技术路线：

`静态头像 -> 嘴部 ROI -> 多嘴型贴图 -> 音频/关键点驱动 -> 局部裁剪与形变`

---

## 当前已经实现的能力

### 1. 基础数字人预览

- 使用 `FastAPI` 提供网页和接口
- 使用 `Canvas` 渲染数字人头像
- 支持文本输入后调用 TTS 播放语音

### 2. 单层嘴部贴图驱动

- 用嘴型 PNG 贴图替代早期黑色椭圆
- 支持 `m / a / ai / e / ee / i / o / ou / smile / u` 等嘴型素材
- 可在固定 ROI 区域内绘制嘴部贴图

### 3. 双驱动模式

- `语音驱动`
  根据音频频域 + 时域特征估算嘴型
- `摄像头关键点驱动`
  根据 MediaPipe FaceMesh 提取嘴部关键点，驱动嘴型和形变

### 4. 局部形变能力

- 嘴型切换支持平滑过渡
- 支持连续参数：
  - 横向缩放
  - 纵向缩放
  - 偏移
  - 开口强度
  - 圆唇强度
  - 扁嘴强度
- 支持条带式局部变形
- 支持嘴部轮廓裁剪
- 当前版本已对嘴角稳定性、上下唇分离和条带割裂做过一轮优化

### 5. 调参系统

- 支持页面内实时调节：
  - ROI X / Y / 宽度 / 高度
  - 轮廓高度 / 宽度
  - 条带数量
  - 上下错位强度
  - 中部鼓起强度
- 支持调试面板实时显示当前状态
- 参数会自动保存到本地 `tuning_config.json`
- 页面重新加载时会自动读取保存参数

## 核心文件说明

### `main.py`

负责：

- 提供首页页面
- 提供 TTS 接口
- 提供参数配置读写接口 `/config`

### `static/index.html`

负责：

- 页面布局
- 左侧调参区
- 右侧数字人预览区

### `static/main.js`

负责：

- 头像绘制
- 嘴型贴图渲染
- 语音驱动
- 摄像头关键点驱动
- 局部条带形变
- 嘴部轮廓裁剪
- 参数实时调节与自动保存

### `tuning_config.json`

负责保存当前调好的参数，页面加载时会自动读取。

## 当前方案的优点

- 工程复杂度可控
- 可视化效果已经明显优于简单椭圆嘴巴
- 支持两种驱动模式，便于学习对比
- 调参效率高，适合快速实验
- 已经具备“一个可持续迭代的 2D 嘴型实验台”的基础

---

## 当前方案的局限

这套方案虽然已经比较完整，但它仍然是 `单层嘴部贴图` 路线，存在天然上限：

1. 上下唇、牙齿、口腔内部仍然是单层图像表达，结构不够真实。
2. 局部形变本质还是 2D 贴图变形，不是严格的口部几何驱动。
3. 语音驱动仍然是基于音频特征的近似分类，不是严格的 viseme / phoneme 对齐。
4. 嘴角、唇缝、开口内部结构在大幅度动作时仍可能出现假感。
5. 当前更适合做学习和原型验证，不适合作为最终高拟真数字人口型方案。

---

## 当前阶段结论

这个版本已经可以视为：

`单层贴图嘴型方案的阶段性完成版`

继续在这一条路上优化当然还能更好，但性价比已经开始下降。

---

## 推荐的下一步方向

从这里继续升级，优先建议走下面其中一条：

### 方向 1：多层嘴部结构

从单层贴图升级为：

- 上唇层
- 下唇层
- 牙齿层
- 口腔阴影层

这是当前最自然、也最值得继续投入的升级路线。

### 方向 2：更精准的语音驱动

引入：

- viseme / phoneme 对齐
- 时间轴驱动

这样语音模式的嘴型准确度会明显提高。

### 方向 3：角色表现增强

增加：

- 眨眼
- 头部轻微浮动
- 呼吸感
- 待机状态

这样整体观感会更像“数字人”，而不是“只有嘴在动的头像”。

---

## 建议

这一版建议先冻结为基线版本，不再继续大幅度堆单层贴图细节。

更合理的做法是：

`以这个目录为单层贴图基线版本，后续另开新目录继续做多层嘴部方案。`
